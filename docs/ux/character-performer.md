# キャラクターが弾くピアノ — UX 要件（最初の 1 枚）

作成: 2026-11-21 ／ 状態: 草案（キャラの作り方は決定済み・3D の試作 v0 あり：`/character`）。作るものと基準は [character-requirements.md](character-requirements.md)（要件定義 v1）

## 0. デザイン戦略

- **ユーザー層**: 自分（作り手本人）。家で作業・読書・考えごとをしながら、ずっと流しておく人。思い浮かべる 1 人：夜、ひとりで画面に向かって集中している自分
- **ニーズ**（3 つ。優先順）
  1. 誰かがそばにいる安心感：ひとりの作業の時間に、自分のために弾いてくれる存在がいる
  2. 育てている感覚：伝えたことが届き、弾き方がだんだん自分好みになっていくのが分かる
  3. 人に見せたくなる魅力：スクリーンショットや短い動画で、見せたくなる完成度がある
- **渡す価値**: 「この子が、自分のために、いまここで弾いてくれている」と感じられるピアニスト。安心して作業に戻れて、ときどき目をやると応えてくれて、育った姿を人に見せたくなる
- **キャラクター**: 新しく作る。印象派・日本の映画音楽の、落ち着いた優雅な世界観に合うピアノ弾き（ものラジオのキャラとは別）
- **目指す絵**: 本当は 2D の一枚絵がいい。暗く青い部屋、静かに目を伏せた子、手元の小さな光、降る雨や粒子のゆっくりした動き — 「作業用 BGM」の一枚絵の配信のような、絵そのものに浸れる雰囲気（参考：雨の中でフードの子が光る結晶を包む作業用 BGM のサムネイル。雰囲気の参考で、絵柄はまねない）
- **まず 3D で作る**（2026-11-21 決定）：手を鍵盤に合わせて動かす仕組みを先に確かめるため、VRM の 3D キャラで試作する。絵の雰囲気（暗い青・光・粒子・トゥーン調の陰影）は 3D でも寄せる。2D の一枚絵＋差分は、仕組みが固まってから

## 1. 知る（＝思い出す・開くきっかけ）

使うのは自分なので、「知る」は「作業を始めるときに、この子のことを思い出して開く」こと。

- **きっかけの経路**（効く順）
  1. 作業用の PC でブラウザを開いたとき、いつもの場所にある（ピン留めのタブ、管理画面のリンク、ブックマーク）
  2. スマホのホーム画面のアイコン（夜、ベッドで）
  3. 演奏はサーバーでいつも続いているので、開けば途中から聴ける。「始める」手間がない
- **入り口を太くする打ち手**
  - 開いた瞬間に、もう弾いている姿と音がある（待ち画面・読み込み中を見せない）
  - タブのアイコンとタイトルに、いま弾いていることが出る（「♪ 曲 12・E♭ major」など）
- **副次的な経路**（ニーズ 3）：他の人は、自分が共有したスクリーンショット・短い動画・GitHub から知る。その入り口は、共有のしやすさ（「使う」の要件）で太くする

## 2. アクセスする

- **状況**
  - 主：作業用の PC。ブラウザの別タブか、画面の隅の小さなウィンドウ。**目は作業に向いていて、見るのはときどきの一瞥**。耳はスピーカーかイヤホン。何時間も開きっぱなし
  - 副：スマホ（夜・休憩）。縦の小さい画面、片手、音はイヤホン
  - 手はキーボードの上。評価のためにマウスへ持ち替えたくない
- **そこから来る製品の形への制約**
  - **音だけで成り立つ**。見ていない時間がほとんどなので、絵は音を邪魔しない（点滅・大きな動き・通知音を出さない）
  - **一瞥で伝わる**。小さなウィンドウ（幅 320px 程度）でも、弾いている・止まっている・反応した、が分かる
  - **画面の隅に置ける**。ほかのウィンドウの上に小さく浮かべておける形（ピクチャー・イン・ピクチャー）
  - **何時間も軽い**。長時間開いていても、PC が熱くならない・ファンが回らない程度の負荷
  - **作業から手を離さずに伝えられる**。評価はキー 1 つ（いまの `+` `-` を、浮かべた小窓からも）

## 3. 使う（要件レベル）

- **必要な機能・コンテンツ**
  1. **聞こえている音と動きが合う**：鍵盤が押される・手がその音域へ動く・ペダルの足、が、**自分の耳に届いている音**と合っている（配信の遅れを補正する。いまの評価と同じ「聞こえている時刻」の考え方）
  2. **演奏する人としての気配**：テンポやルバートに合わせた体の揺れ、曲の始めの構え、曲の終わりの余韻と手を下ろす動き、曲と曲のあいだの小さな仕草（息をつく・楽譜をめくる）
  3. **伝えたことへの反応**：「いい」でうれしそうに、「微妙」で少し考えて弾き方を変える、言葉の指示には軽くうなずく。反応は小さく、作業の邪魔にならない
  4. **育っていく姿が見える**：何回聴いてもらったか、何を覚えたか（例：「あなたは静かな夜の曲が好き」）を、この子の言葉や持ち物（楽譜帳など）で見せる。好みの 15 個の数値は、裏側に置く
  5. **時間に寄り添う**：朝・昼・夜で部屋の明かりが変わる。止めているときは、ピアノの前で待っている
  6. **見せたくなる**：小窓でも全画面でも絵になる構図。いまの一場面を画像で保存、短い動画（数十秒）で保存できる
- **品質の水準**
  - 音と動きのずれは、聴いていて気にならない程度（目安 0.1 秒以内。要確認）
  - 手が鍵盤と合っていない（届かない音を弾いている）ように見えない
  - 同じ仕草の繰り返しに見えない（何時間見ても、ときどき違う）
  - 一枚絵として、人に見せて恥ずかしくない
- **まだ決めないこと**
  - キャラの見た目・作り方（2D の差分画像／Live2D／3D の VRM）。手と鍵盤を合わせる難しさで選ぶ（下の「未確認」）
  - 画面の配置・色・ボタン
  - ~~いまの操作画面（スライダー・ログ）との関係~~ → 2026-11-24 決定：操作画面はなくし、キャラの画面だけにする。言葉・一時停止・保存はキャラの画面へ移し、スライダーはなくす

## 4. 結果

1. **ユーザーに残る感情**
   - 「ひとりじゃない。この子が、自分のために弾いてくれている」— 安心して作業に戻れる
   - 「伝わった。自分のことを分かってきてくれている」— うれしさ、愛着
   - 「この子を見てほしい」— ちょっとした誇らしさ
2. **作り手が求める結果**（感情の後からついてくるもの）
   - 毎日、作業のときに開く（開いている時間が長い）
   - 評価・言葉が増える（好みを学ぶ材料が溜まる）
   - スクリーンショット・動画の共有、GitHub での反応
   - その結果のために必要な感情：開くのは「そばにいてほしい」から／評価するのは「伝えたら応えてくれる」から／共有するのは「この子が誇らしい」から

## 5. 道筋の穴

| ステージ | 感情が途切れる箇所 | 対策の当たり |
|---|---|---|
| 知る | 作業を始めるとき、開くのを忘れる | ピン留めタブ・ホーム画面に置く。開けばもう弾いている |
| アクセス | 作業中は見ていないので、キャラがいる意味が薄れる | 一瞥で状態が分かる小窓。反応は目をやったときに見える程度の残り方（しばらく表情が残る） |
| アクセス | 評価のためにマウスに持ち替えるのが面倒で、伝えなくなる | キー 1 つ、小窓から。伝えた瞬間にキャラが応える |
| 使う | 手と音がずれると「作り物」に見えて、安心感が壊れる | 聞こえている時刻に合わせる。合わせられない動き（細かい指）は描かず、手の位置と強さで見せる |
| 使う | 同じ動きの繰り返しで、数時間で飽きる | 曲・テンポ・時間帯で仕草を変える。ランダムな小さな仕草 |
| 結果 | 好みに寄っていても、変化に気づけない | 覚えたことをキャラの言葉で見せる。ときどき「前より静かに弾くようになりました」 |
| 結果 | 共有したくても、操作画面ごと写ってしまう | キャラだけの構図で画像・動画を保存 |

## 6. 未確認・仮置き

- **キャラの作り方**：まず 3D（VRM）で試作すると決めた。2D は後で。以下は比較のメモ。手と鍵盤を合わせるには、腕・手の位置が音域で変わる必要がある
  - 2D 差分画像（ものラジオ方式）：作りやすいが、手の位置の差分が多く要る。口や目の差分の方式は流用できる
  - Live2D：動きは滑らかだが、モデルを作るのに専用ソフトと手間が要る
  - 3D（VRM、VRoid Studio で作れる）：手を鍵盤の位置へ動かせる（companion-service で VRM を使った経験あり）。絵柄は 3D 調になる
- **音と動きのずれの許容量**（目安 0.1 秒）は未確認。試作で確かめる
- **長時間の負荷**：3D や大きなアニメーションをブラウザで何時間も動かしたときの CPU / GPU 負荷は未確認。この PC は YOU で GPU を常に使っている
- **ピクチャー・イン・ピクチャー**：Chrome の Document Picture-in-Picture は使えるが、Safari・スマホは未対応（推定。要確認）
- **キャラの素材の権利**：AI で絵を作るなら、そう明記する（ものラジオと同じ方針）
- **公開の試聴ページ**（GitHub Pages）にもキャラを出すかは未決。出すなら、録音に合わせて動かす形になる
- **試作の仮のキャラ**：手元にある VRM は自作のキャラ 1 体だけ（VRM 0.x、14MB、再配布禁止、メタデータに連絡先メールが入っている）。試作に使うなら手元だけで読み込み、リポジトリには入れない・公開ページには出さない。新しいキャラは VRoid Studio などで別に作る
