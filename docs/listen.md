# 好きな曲を聴いて曲調を覚える（音声・URL）

画面の入力欄に YouTube などの URL を貼るか、`piano learn` に音声ファイルか URL を渡すと、その曲を聴いて曲調の値を推定し、今の好みをそちらへ寄せます（重み 0.5。上書きはしない）。
覚えるのは**曲調の数値だけ**で、旋律や和音の並びは持ち帰りません。弾くのは、似た雰囲気の別の曲です。

```bash
.venv/bin/pip install -e '.[listen]'
.venv/bin/pip install --no-deps 'basic-pitch==0.4.0'   # TensorFlow を要求するが使わない（同梱の ONNX 版で動かす）
.venv/bin/piano learn https://www.youtube.com/watch?v=...
.venv/bin/piano learn 好きな曲.mp3 好きな曲.mid          # 音声と MIDI を混ぜてもよい（平均して取り込む）
```

ffmpeg が要ります。GPU は使いません（書き起こしは CPU で 1 曲 1 秒ほど、URL の取得を含めて 10 秒前後）。

## 流れ

1. URL なら yt-dlp で音声だけを一時ディレクトリに取る。解析が終わったら消す（保存も配布もしない）。30 分より長いもの・ライブ配信は断る
2. ffmpeg で 22.05kHz モノラルにする。長い曲は頭の 10 秒を飛ばして 6 分だけ使う
3. [Basic Pitch](https://github.com/spotify/basic-pitch)（Spotify、Apache-2.0）で音符に書き起こす
4. テンポは librosa で音声から推定する（書き起こしからは分からない）。推定したテンポの倍の周期の方が、音の立ち上がりの繰り返しがはっきり強ければ、速い曲を半分と読んだとみて倍にする
5. 曲の盛り上がり（4 秒ごとの音量の、山 − 最初の 12 秒）から、盛り上がりの大きさ（`drama`）を推定する
6. 音符を拍に直し、MIDI からの推定（`reference.estimate`）と同じ換算で値を出す。書き起こしでずれる値は直線で補正する

## 推定する値・しない値

| 値 | 音声から | 理由 |
|---|---|---|
| テンポ | する | |
| 和音の色彩 | する（補正あり） | |
| 短調の多さ | する | 長調か短調か（0.2 / 0.8） |
| 旋律の音域 | する（補正あり） | |
| 旋律の跳躍 | する（補正あり） | |
| 盛り上がりの大きさ | する | 60 秒以上の曲だけ。盛り上がり +3.3dB → 0、+10.7dB → 1（この生成器で drama を 0 と 1 にして弾いたときの中央値） |
| 旋律の音の多さ | **しない** | 書き起こしでは旋律と伴奏が分かれず、当て推量と同じだった（下） |
| 弱さ | **しない** | 書き起こしの音量は録音・ミックスの音量に左右されるので使わない（未検証） |
| 3 拍子 | **しない** | 音声から確かめる方法を用意していない |
| 余白・ヨナ抜き度など | しない | MIDI からも推定していない（当てにならなかった） |

## どれだけ当たるか

`tools/eval_listen.py` で数えました（2026-11-24）。設定 θ を乱数で決めて 1 曲ずつ弾き、128kbps の MP3 にしてから書き起こして推定し、元の θ と比べます。補正の式は `--seed 1` の 24 曲で決め、`--seed 2` の別の 24 曲で確かめました。

**別の 24 曲（seed 2）で、元の θ との誤差**（小さいほどよい。当て推量 = いつも θ の平均を言う）

| 値 | 同じ曲の MIDI から | 音声から | 当て推量 |
|---|---|---|---|
| テンポ | 0.00 | 0.02 | 0.25 |
| 和音の色彩 | 0.27 | 0.18 | 0.20 |
| 短調の多さ | 0.29 | 0.27 | 0.20 |
| 旋律の音域 | 0.14 | 0.22 | 0.33 |
| 旋律の跳躍 | 0.38 | 0.25 | 0.25 |

- **テンポ**は、生成した 72 曲中 68 曲で当たりました（5% 以内。♩=96 を超えると値は上限の 1 になるので、そこは 1 で当たりとした）。外れた 4 曲は、どれも速めの曲（♩=88〜96）を遅く読んだもの
  - はじめは「1 拍に打鍵が詰まっていたら倍にする」決まりで 48/48 当たっていましたが、ゆっくりで細かいアルペジオの録音（参考の曲、♩≈62）を ♩=123 と読んだのでやめました。今は「倍の速さの周期の方が、音の立ち上がりの繰り返しが 2 倍以上強ければ倍にする」です。その比は、生成した曲でテンポが当たったものが最大 1.45、参考の録音が 1.36、速いジャズが 2.71
  - この決まりと、librosa に置く事前のテンポ（60）は、生成した曲と 3 つの録音を見て決めたので、テンポについては別の組で確かめたとは言えません
- **盛り上がりの大きさ**（`drama`、2026-11-24 に追加）は、別の 24 曲（seed 2）で元の値との相関 0.82、誤差 0.19（当て推量 0.26）
- **伴奏の細かさ**（`ripple`、2026-11-24 に追加）は、1 拍あたりの打鍵の時刻の数から読みます。`--seed 1` の 24 曲で、ripple 0 → 2.44 打/拍、1 → 4.62 打/拍の直線に決めました（相関 0.77。flow・density・テンポとの相関は 0.1 以下）。別の 24 曲（seed 2）で相関 0.75、誤差 0.17（当て推量 0.25）
- **短調の多さ・跳躍**は、元の θ と比べると当て推量と変わらないか、悪いです。ただし同じ曲の MIDI から推定しても同じくらい悪いので、書き起こしで失ったのではありません。この生成器は θ を確率として使う（短調の多さ 0.4 でも長調で弾くことがある）ので、1 曲の音から θ を当てること自体に限界があります
- 書き起こしで何を失ったかは、**同じ曲の MIDI からの推定との一致**で見ました。長調か短調かは 2 組とも 92% 一致、相関は和音の色彩 0.87 / 0.87、音域 0.82 / 0.95、跳躍 0.53 / 0.67（seed 1 / seed 2）
- **旋律の音の多さ**は、補正しても誤差 0.29（当て推量 0.30）だったので推定から外しました

## 実際の録音で

数えたのは、この生成器のピアノ（きれいな音源・残響なし）の音だけです。実際の録音では、残響・ほかの楽器・歌で書き起こしが崩れるので、もっと悪いはずです。確かめたのは次の 3 曲だけです。

| 曲 | 推定 | 実際 |
|---|---|---|
| サティ「ジムノペディ第 1 番」（ピアノソロ、YouTube） | ♩=66・長調・和音の色彩 0.26（素朴）・跳躍 0.39・盛り上がり 0.22 | ゆっくり（Lent）・ニ長調寄り・素朴な和音・順次進行が多い・起伏が小さい。合っている |
| 「C Jam Blues」（ジャズピアノ、YouTube） | ♩=118（上限の 1.00）・長調・和音の色彩 1.00・盛り上がり 0.08 | 速いスウィング・ブルース・テンションだらけ・ずっと同じ勢い。合っている（倍にする決まりを入れる前は ♩=59 と出ていた） |
| 「忘れじの最果て（piano ver.）」（プトリカ 1st.cut、YouTube） | ♩=62・長調・和音の色彩 1.00・盛り上がり 0.62・伴奏の細かさ 1.00（4.98 打/拍） | ゆっくり・細かいアルペジオ・不思議な和音が多い・50 秒かけて盛り上がる。合っている（ripple を入れる前は、生成器に 16 分のアルペジオがなく、好みを寄せても 1 拍 2.8 打で、音の細かさが似なかった。ripple = 1 で 4.3 打） |

歌もの・オーケストラ・ドラムの入った曲は試していません。

## 画面から渡せる URL

UI サーバーには認証がないので、画面（`POST /api/learn`）から渡せるのは YouTube・ニコニコ動画・SoundCloud の URL だけにしています。yt-dlp は任意の URL を取りに行けるため、同じネットワークの人に PC から内側のサービスを叩かせないためです。ターミナルの `piano learn` には制限がありません。

YouTube の利用規約は、動画のダウンロードを原則として認めていません。ここでは手元で解析にだけ使い、すぐ消しますが、使うかどうかは自分で判断してください。

## 和音の進行（harmony.py）

答えの分かっている amane 自身の曲を MP3 にして書き起こし、読んだ和音と弾いた和音を比べた（`tools/eval_chords.py`、各 12 曲）。
和音を変える罰（`SWITCH`）は seed 1 で 0〜2 を比べて 1.5 に、調の決め方（主和音の長さと最後の和音を足す）は seed 1・2 を見て決めたので、seed 3 が決めるのに使っていない組。

| | seed 1 | seed 2 | seed 3 |
|---|---|---|---|
| 半拍ごとの根音 | 82% | 79% | 79% |
| 根音と長短（maj / min / sus） | 70% | 70% | 69% |
| 調（主音と長短） | 12/12 | 10/12 | 11/12 |
| 進行の型 A の根音（4 つのうち） | 73% | 62% | 60% |
| 同じ長短の amane の型を当てずっぽうで選んだとき | 39% | 42% | 37% |

- 長短の取り違えは、9th の入った和音を sus2 と読むものが多かった（9th の型を足し、sus を少し選びにくくして 63% → 70%、seed 1）
- 調は、音の分布だけだと属調（5 度上）と平行調に取り違えた（seed 1・2 で 24 曲中 6 曲）
- 借りた進行で弾くと濁りが増える（`tools/melody_stats.py`、覚えた 5 曲の進行で 24 曲）：旋律と伴奏が半音で隣り合う 0.6% → 0.8%、和音にない音で伴奏と濁る長さ 3.6% → 5.1%（調の中の和音）・2.6% → 4.8%（調の外の和音）。読んだ分数和音の低音を付けると隣り合いが 1.1% に増えたので、低音は使わない

## 旋律の癖（habits.py）

旋律そのもの（音の並び）は写さず、2 つの分布だけを数える：1 拍の中で旋律が鳴り始める位置の並び（16 分の 4 マス）と、となりの旋律音が音階で何歩動くか。
答えの分かっている amane 自身の曲を MP3 にして書き起こし、作曲した旋律の癖と比べた（`tools/eval_habits.py`、各 12 曲。曲ごとの割合の相関 r）。旋律の取り出し方（上位 30% の高さ、直前 4 音の中央より 7 半音を超えて低い音は伴奏とみなす）は seed 1 で決めた。

| | seed 1 | seed 2 |
|---|---|---|
| 8 分（"x.x." と "..x."）の割合 | 0.92 | 0.74 |
| 隣の音へ動く割合 | 0.69 | 0.81 |
| 1 拍の打鍵の数 | 0.52 | 0.16 |
| 同じ音が続く割合 | 0.92 | −0.01 |
| 3 歩以上跳ぶ割合 | 0.65 | 0.22 |
| 16 分を含む拍の割合（読み / 本当、平均） | 0.14 / 0.03 | 0.24 / 0.03 |

- 当たると言えるのは 8 分の割合と、隣の音へ動く割合くらい。16 分と跳躍は多めに読む（伴奏の細かい音が旋律に混ざる）
- そのため読んだ癖は、amane 自身の癖（seed 1 の作曲した旋律の平均）と半分ずつ混ぜてから使う（`habits.TRUST`）
- 覚えた 5 曲の癖で弾くと、作曲した旋律の癖は読んだ癖に近づいた（各 12 曲、違い＝全変動距離）：リズム 0.50 → 0.36、音の動き 0.37 → 0.34（音の動きは、強拍で和音の音に着く決まりなどが勝つので、ほとんど動かない）
- 旋律の質（`tools/melody_stats.py`、5 曲の進行で 24 曲。進行だけ → 癖も）：止まる小節 2.9% → 4.5%、隣で濁る 0.8% → 1.1%、和音と濁る長さ 5.1% → 3.3%（調の中）・4.8% → 4.9%（調の外）、順次進行 71% → 61%。癖で弾くときは短い音も和音と半音でぶつからない音にした（しないと隣で濁る 1.7%）

## 耳コピの書き起こし（cover.py）

答えの分かっている amane 自身の曲を MP3 にして書き起こし、弾いた音と比べた（`tools/eval_cover.py`、各 6 曲。同じ音高で出だしが 50ms 以内を当たり）。

| | seed 1：適合率 / 再現率 / F 値 / 強さの誤差 | seed 2 | 時間（音の長さの倍率、この PC の CPU） |
|---|---|---|---|
| Basic Pitch（楽器を問わない） | 0.62 / 0.86 / 0.72 / 20.9 | 0.64 / 0.91 / 0.75 / 17.8 | 0.01 |
| Transkun（ピアノ専用） | 0.99 / 0.99 / 0.99 / 10.2 | 0.99 / 0.99 / 0.99 / 9.0 | 0.19 |

- amane のピアノの音（サンプリングのピアノ）なので、実際の録音（部屋の響き・別のピアノ）より当てやすいはず。実際の録音での当たり方は、答えがないので測っていない
- 曲調の推定（テンポ・進行・旋律の癖）は、Basic Pitch の書き起こしで換算を決めてあるので Basic Pitch のまま。Transkun は耳コピで弾く音だけに使う
- やめたこと：弾くたびに、元の音と自分のピアノで弾いた音の響き（CQT）を比べて、音の強さを決め直し・余計な音を捨てる。響きの違いは 2 割ほど縮むが、F 値は変わらず、強さは本当の強さから遠ざかった（Basic Pitch 20.9 → 21.7、Transkun 10.2 → 27.2）。響きの違いは F 値 0.72 と 0.99 の書き起こしでほぼ同じ値（0.379 / 0.381）で、物差しとして使えなかった。ほかに、取りこぼしの候補を足す・捨てる割合を回ごとに上げる・長さや出だしを合わせ直す・時刻をずらした書き起こしの多数決も試したが、どれも F 値が上がらなかった
